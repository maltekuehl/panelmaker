# Running Your Own Instance

PanelMaker is open source and designed to be self-hosted. Any research group or institution can run its own instance, with its own users, labs, panels, and validation reports, independent of any other deployment.

## Before you start

An instance needs:

- Docker with the Compose plugin, or Node.js 24 and PostgreSQL for an install without Docker
- A hostname with a TLS certificate. Production builds only work over HTTPS, except on `localhost`
- Outbound HTTPS to a few public services (OLS4, NCBI, UniProt, SciCrunch, FPbase) for ontology and antibody lookups

Email and password sign-in works out of the box. GitHub sign-in and the AI assistant are optional. There is no shared AI key: the assistant runs on keys set by the operator, a lab, or each user.

Search engines are kept out by default: robots.txt disallows everything, the sitemap is empty and pages are marked `noindex`. Set `INSTANCE_ALLOW_INDEXING=true` only for a public instance you want listed.

## Quick start

```bash
git clone https://github.com/complextissue/panelmaker.git
cd panelmaker
cp .env.local.example .env
# edit .env: NEXT_PUBLIC_BASE_URL, AUTH_SECRET, POSTGRES_PASSWORD, INSTANCE_* settings
docker compose up -d --build
docker compose run --rm migrate npm run admin:create -- --email you@example.edu --name "Your Name"
```

Every `docker compose up` applies database migrations and loads the reference data (ontology terms, marker proteins, imaging methods, fluorophores) before the app starts. The last command creates the first admin and prints a one-time password.

## Getting help

If you run into issues deploying your own instance, open an issue or a discussion on [GitHub](https://github.com/complextissue/panelmaker/issues). Report security problems privately, as described in the [security policy](https://github.com/complextissue/panelmaker/blob/main/SECURITY.md).
