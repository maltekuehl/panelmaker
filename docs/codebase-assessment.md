# PanelMaker codebase assessment

Date: 2026-09-22. Method: nine scoped finder agents read the repository in full (about 650 file reads), then every finding was checked by two independent reviewers, one trying to refute it and one judging whether acting on it is worth doing. 440 unique findings were raised, 11 were rejected, 429 survived. The last 40 were verified by hand after the agent run hit a usage limit.

Baseline before any change: TypeScript reports no errors, ESLint reports 4 warnings and no errors, Prettier is clean.

Owner constraints applied to the ordering: the product is pre-launch and runs only as a local dev setup, so development speed outranks hardening; the domain focus is antibody-based multiplexed immunofluorescence, with metal tags and mass spec as later extensions.

## What is solid

The architecture holds up. The `models/<entity>/` pattern is applied consistently across fourteen entities, and the split between queries, transforms and schema is real rather than nominal. The two-lane visibility system for labs is genuinely careful: access predicates are pure and unit tested, a guard test stops client bundles importing server-only code, and the public lane never consults the viewer. Cache Components is adopted without the usual mistake of calling `auth()` inside a cached scope. The design system is applied evenly, and the de-carding rules in the house style are followed on the pages that were rewritten for them.

## The main systemic problems

**Half-finished migrations leave two of everything.** There are two API response helpers, two mobile breakpoint hooks, two toast systems, two chat surfaces, two token telemetry tables, two NextAuth mounts and two near-identical usage tables. In each case one side is dead or invisible, and the dead side is what several call sites use. The toast case is the clearest: six screens call a store that no provider consumes, so those notifications never appear.

**Error handling is a string-matching protocol.** Seventeen routes throw `Error` with a message, then other code matches substrings of that message to pick a status code. `ApiException` exists for exactly this and is never used. Renaming an error message silently changes an HTTP status.

**The seed is the weakest artifact in the repo.** Seven marker proteins carry UniProt accessions belonging to other proteins, so the seeded E-Cadherin page shows amyloid precursor protein. `resetDatabase` deletes reports but not experiments, so every re-seed accumulates orphans. 2300 of its 3027 lines are inlined data.

**Tests mostly cannot fail.** Console-error listeners attach after navigation, assertions sit inside existence guards that skip when the element is missing, the API specs assert a response envelope no route returns, and several specs still target BioContextAI routes that were removed.

## Highest-value changes

In order: fix the flows that are broken right now, make toasts visible, repair the chat wiring, and correct the seed. Those four are mostly small independent edits and they remove the daily friction of developing against this codebase. Deleting dead code comes next because it shrinks the surface every later change has to consider.

## What was implemented

All 14 packages were worked in one pass by six agents on disjoint directories, plus the lead agent on
root and config files. Result: 287 files changed, 5540 insertions, 13788 deletions, so the codebase is
about 8000 lines smaller.

Verification after the work, all from a clean run:

| Gate | Result |
|---|---|
| `npx tsc --noEmit` | 0 errors |
| `npm run lint` (prettier + eslint) | 0 errors, 3 warnings (all pre-existing library limitations) |
| `npm run test:unit` | all assertions pass |
| `npm run build` | succeeds, every route prerenders |
| Runtime smoke test, 15 pages and API routes | all 200 |
| Em dash, en dash, middle dot in source | 0 |

The eslint `no-unused-vars` rule was switched from off to error, which required wiring the TypeScript
plugin instance that `eslint-config-next` registers into the project config object. It found four real
unused bindings, all removed.

37 unused dependencies were removed, including 20 individual `@radix-ui/*` packages that the `radix-ui`
umbrella already provides. `hast-util-sanitize` was promoted from a transitive to a direct dependency
because `components/markdown.tsx` imports it.

### Still open, needing your decision

1. `git rm TODO.md prisma/proposed_schema_draft.dbml`. Both are stale (they describe a SQLite and MCP
   registry project) and every item in TODO.md is checked off. The permission layer blocked the deletion.
2. Re-seed to pick up the corrected UniProt accessions: the database still holds the wrong protein rows
   because `prisma db seed` wipes all data and was not run. Run `npx prisma db seed` then
   `npm run seed:demo-user` when convenient.
3. Email addresses are stored unnormalised at registration, so case variants break login. Fixing one
   side alone would lock out existing mixed-case accounts, so it needs a lowercasing data migration.
4. The model catalog in `lib/ai/models.ts` was deliberately left untouched. Whether `claude-sonnet-4-6`,
   `gemini-3.5-flash` and `gpt-5.5` are current ids was not verified, and an earlier agent's unverified
   edit to `DEFAULT_MODEL` was reverted.
5. Secrets in `.env.test` and `.env.local.example` are now distinct placeholders, but the values
   previously committed to the public repo are still in git history. You said you will rotate before launch.
