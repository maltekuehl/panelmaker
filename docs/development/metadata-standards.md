# Metadata standards, ontologies, and external APIs for PanelMaker

Research date: 2026-09-22. A read-only review of this repository at that date; some gaps listed here have since been closed.

Scope: what PanelMaker stores today, what the closest community standards require (SDRF-Proteomics, EBI spatial transcriptomics metadata, MITI, HuBMAP OMAP and ASCT+B, REMBI and OME-NGFF, plus IDR, MIFlowCyt, HCA and CELLxGENE as secondary references), which ontology fits each field, which export and import formats to add, which external APIs are worth wiring in, and a prioritized plan.

Every URL cited below was fetched during this research. Where a detail could not be verified from a fetched source, the text says so.

---

## 1. Current state of PanelMaker metadata

Sources read: `prisma/schema.prisma`, `src/lib/ontology.ts`, `src/app/api/ontology/route.ts`, `src/lib/integrations/*.ts`, `src/components/ontology-combobox.tsx`, `src/components/ontology-multi-combobox.tsx`, `src/components/submit/*.tsx`, `src/components/submit/types.ts`, `src/models/experimental-report/schema.ts`, `src/models/experiment/schema.ts`, `src/models/antibody/schema.ts`, `src/models/panel/schema.ts`, `src/models/panel/intelligence.ts`, `src/app/api/panels/[id]/export/route.ts`.

### 1.1 How ontology lookups work today

`src/lib/ontology.ts` calls the OLS4 v1 search endpoint (`https://www.ebi.ac.uk/ols4/api/search?q=...&ontology=...&rows=10`, with a wildcard retry) for `cl`, `uberon`, `go` (client-filtered to `GO:` ids), `doid`, and `ror`. Species go through NCBI E-utilities (`esearch` then `esummary` on `db=taxonomy`) and are stored with the id string `NCBI:txid{uid}`. Results are cached with `next: { revalidate: 3600 }` for OLS4 and not cached at all for NCBI. There is no term lookup by id, no ancestor or descendant traversal, no obsolete-term handling, and no id-format validation in Zod (`ontologyValueSchema` is `{ id: string, label: string }`).

The `OntologyCombobox` and `OntologyMultiCombobox` client components debounce queries against `/api/ontology?type=<cl|uberon|ncbi_taxonomy|go_cc|doid|ror>&q=`, require two characters, and store `{ id, label }` pairs. The submit API accepts those pairs (`ontologyValueSchema` in `src/models/experimental-report/schema.ts`) and the schema stores them in the `CellType`, `Tissue`, `Taxon`, `CellularComponent`, and `DiseaseCondition` tables.

### 1.3 Metadata a spatial proteomics experiment needs that is missing entirely

Grouped by the standard that requires it (details in section 2):

- Donor and sample level: sex, age, developmental stage, ancestry, donor or sample identifier, biological replicate, sample type (tissue, cell line, organoid, primary culture), cell line accession (Cellosaurus), anatomical region beyond the organ, healthy versus diseased status separate from the diagnosis.
- Specimen preparation: preservation method separate from fixative, fixative and concentration, fixation duration, section thickness (um), slide type or charge, storage temperature, mounting medium, permeabilization, protocol DOI (protocols.io).
- Imaging assay level: imaging modality (FBbi), instrument make and model, objective magnification, numerical aperture, immersion medium, physical pixel size x/y/z with unit, field of view, z-stack and time series flags, acquisition software, acquisition date, fiducial marker.
- Channel level: channel id and name, excitation and emission wavelength and bandwidth, exposure time, detection chemistry (direct conjugate, indirect secondary, oligo barcode with strand sequences, metal isotope element and mass), lot number, concentration in ug/mL, QC pass flag with reason.
- Antibody level: isotype, recombinant flag, target species as ontology ids, HGNC id of the target.
- Image level (ReportImage): pixel size, channels shown, which markers, objective, format, scale, region of interest, link to full dataset (BioImage Archive S-BIAD, IDR, HuBMAP).
- Provenance: author ORCIDs on experiments and panels, reviewer ORCIDs, panel version, source OMAP id, data DOI, manuscript DOI, protocol DOI.
- Export and import: no SDRF, MITI, OMAP, or REMBI format; only a house JSON and two CSVs (`format=json|csv|order`).

## 2. Standards reviewed

### 2.1 SDRF-Proteomics (HUPO-PSI)

Fetched: https://sdrf.quantms.org/ , https://github.com/bigbio/proteomics-sample-metadata/blob/master/sdrf-proteomics/README.adoc , https://raw.githubusercontent.com/bigbio/proteomics-sample-metadata/master/llms.txt , https://raw.githubusercontent.com/bigbio/proteomics-sample-metadata/master/sdrf-proteomics/TERMS.tsv , https://raw.githubusercontent.com/bigbio/sdrf-templates/main/templates.yaml , https://raw.githubusercontent.com/bigbio/sdrf-templates/main/base/1.1.0/base.yaml , https://raw.githubusercontent.com/bigbio/sdrf-templates/main/sample-metadata/1.0.0/sample-metadata.yaml , https://raw.githubusercontent.com/bigbio/sdrf-templates/main/human/1.1.0/human.yaml , https://raw.githubusercontent.com/bigbio/sdrf-templates/main/affinity-proteomics/1.0.0/affinity-proteomics.yaml , https://raw.githubusercontent.com/bigbio/sdrf-pipelines/main/README.md

What it is. A tab-delimited file (`.sdrf.tsv`) where each row links one sample to one data file. It is MAGE-TAB SDRF compatible and is the HUPO-PSI standard for proteomics sample metadata. Templates are layered: `base` (infrastructure) is extended by `sample-metadata`, which is extended by a technology layer (`ms-proteomics`, `affinity-proteomics`, `ms-metabolomics`), a sample layer (`human`, `vertebrates`, `invertebrates`, `plants`, `clinical-metadata`, `oncology-metadata`) and experiment layers (`cell-lines`, `dia-acquisition`, `single-cell`, `crosslinking`, `immunopeptidomics`, `metaproteomics`, `olink`, `somascan`). Each template is a YAML file that the `sdrf-pipelines` validator reads.

Column conventions (exact):

- Anchor columns: `source name` (unique sample id, PRIDE:0000623), `assay name` (unique run id, NCIT:C178857), `technology type` (PRIDE:0000663, fixed values: `proteomic profiling by mass spectrometry`, `protein expression profiling by antibody array`, `protein expression profiling by aptamer array`).
- `characteristics[...]` for sample properties, `comment[...]` for data-file and technical properties, `factor value[...]` for the studied variables. Column names are lowercase and case-sensitive, with no space before the bracket. Order is characteristics, then comments, then factor values.
- Multi-valued columns are expressed by repeating the whole column with the same header (cardinality `multiple`), e.g. `characteristics[organism part]`, `characteristics[cell type]`, `comment[modification parameters]`, `comment[sdrf template]`.
- Ontology values: either the exact term label (for sample characteristics that match EFO) or the key value form `NT={name};AC={accession}`; extended for modifications to `NT=Oxidation;AC=Unimod:35;TA=M;MT=Variable;PP=Anywhere`; template versions use `NT=human;VV=v1.1.0`.
- Reserved words (lowercase): `not available`, `not applicable`, `anonymized`, `pooled`. Each template column declares `allow_not_available`, `allow_not_applicable`, `allow_pooled`, `allow_anonymized`.
- Uniqueness: `source name` + `assay name` + `comment[label]` must be unique; `assay name` must be unique across the file except for multiplexed runs, where rows share `assay name` and differ in `comment[label]`.
- Replicates: `characteristics[biological replicate]` (integer or `pooled`, numbering restarts per condition) and `comment[technical replicate]` (integer from 1). Fractions: `comment[fraction identifier]` (1 when not fractionated). Labels: `comment[label]` with values such as `label free sample`, `TMT126`, `TMT127N`, SILAC variants, iTRAQ channels.

Mandatory columns by template (from the YAML files and the spec):

Ontologies by column (TERMS.tsv and spec): NCBITaxon (organism), UBERON and BTO (organism part, sampling site, biopsy site, metastasis site), CL, BTO, CLO (cell type), MONDO, EFO, DOID, PATO (disease; `normal` = PATO:0000461), HANCESTRO (ancestry), EFO (developmental stage, treatment, genetic modification), PATO (sex, phenotype), CLO and Cellosaurus (cell line), ChEBI (compound), NCIT (staging, grading, dose), PSI-MS and PRIDE (instrument, acquisition, platform), Unimod and PSI-MOD (modifications), ENVO (metaproteomics).

Validator. `pip install "sdrf-pipelines[ontology]"` then `parse_sdrf validate-sdrf --sdrf_file file.sdrf.tsv --template human`. The template YAML schema has per column: `name`, `ontology_accession`, `description`, `requirement` (required, recommended, optional), `cardinality`, `allow_*`, and `validators` (`ontology` with `ontologies` and optional `parent_term`, `pattern`, `values`, `semver`, `single_cardinality_validator`).

What transfers to imaging proteomics. The sample layer transfers unchanged: organism, organism part (multiple), cell type (multiple), disease with the PATO `normal` convention, material type, sex, age pattern, developmental stage, ancestry, individual, biological replicate, cell line with Cellosaurus. The reserved words and the `NT=;AC=` syntax transfer. The layered template plus YAML validator design is the right model for a PanelMaker "imaging" template. The MS-specific columns (label, fraction, cleavage agent, modification parameters, acquisition method) do not transfer. The multiplexing rule (rows share `assay name`, differ by label) is the natural way to express one image with many channels: one row per channel. Note that the `technology type` fixed list has no imaging value; a PanelMaker export would either use `protein expression profiling by antibody array` (closest existing value, semantically loose) or propose a new PRIDE CV term. I could not verify whether HUPO-PSI has such a term in progress.

### 2.2 EBI spatial transcriptomics metadata

Fetched: https://www.ebi.ac.uk/spatial-transcriptomics/metadata , https://www.ebi.ac.uk/spatial-transcriptomics/ , https://www.ebi.ac.uk/spatial-transcriptomics/submit , https://www.ebi.ac.uk/bioimage-archive/help-submit-ST/

What it is. EMBL-EBI's cross-resource recommendation for spatial transcriptomics submissions. Sequencing-based data (Visium, GeoMx) go to the ArrayExpress collection in BioStudies through Annotare; imaging-based data (Xenium, MERSCOPE, CosMx) go to the BioImage Archive through BioStudies using a REMBI study component, MIFA annotation components, and file lists. Accepted image formats: OME-TIFF, OME-NGFF (OME-Zarr), or a zipped SpatialData object. The metadata page names NCBITaxon (example `NCBITaxon:9606`) and UBERON (example `UBERON:0002113`) explicitly. MONDO, EFO, and CL are not named on that page, and the page does not mention MAGE-TAB, IDF, or SDRF; I could not verify a platform vocabulary beyond the examples `10x Xenium`, `10x Visium`, `MERfish`.

Field list as published (required unless marked):

- Sample: `Sample ID`, `Slide ID`, `Position on slide` (optional), `Sample preservation method`, `Organism name` (NCBITaxon), `Time from collection to preservation` (hours, optional), `Section thickness` (micrometers), `Protocol for fixing section`, `Organ` (UBERON), `Anatomical region` (UBERON), `Donor health status at sampling`, `Sample disease status` (optional), `Additional sample description` (optional), `Sex`, `Age` (conditionally required), `Developmental stage` (conditionally required for animal models), `Sample collection protocol` (optional).
- Specimen: `Sample preparation protocol` (slicing, dewaxing, de-crosslinking, permeabilization), `Histological classification` (optional), `Permeabilization time` (required for sequencing-based, optional for imaging-based).
- Experimental: `Imaging protocol` (microscope setup, instrument, magnification, technique), `Technology used`, `Custom panel journal reference` (optional), `Custom panel reference code` (optional), `Segmentation signal` (required for imaging-based; antibodies, stains, channels used for segmentation), `Physical pixel size x`, `Physical pixel size y` (micrometers, required for imaging-based), `Physical pixel size z` (conditionally required), `Instrument model` (optional), `Chemistry version`.
- Analytical: `QC and filtering` (optional), `Version of analysis software`, `Method of annotating images` (manual, semi-automated, automated; imaging-based), `Annotation pair` (source image and annotation mask; imaging-based), `Image correlation between H&E and fluorescence` (conditionally required), `Segmentation method` (imaging-based).
- File types, imaging-based: high resolution image, transcript coordinates, cell-level segmentation mask or polygons, probe panel, sample-level segmentation mask (multiplexed samples), field of view regions (optional).

What PanelMaker should adopt. The Sample block minus transcript-specific items: `Slide ID` (string, 1 per sample), `Section thickness` (float, micrometers, 1), `Sample preservation method` and `Protocol for fixing section` (split fixation into preservation plus fixative plus protocol text), `Anatomical region` (UBERON, 0..n per sample, distinct from `Organ`), `Donor health status at sampling` versus `Sample disease status` (two disease fields), `Sex`, `Age`, `Developmental stage`. From Experimental: `Physical pixel size x/y/z` (float, micrometers, 1 per image), `Instrument model` (string), `Segmentation signal` (which channels were used for nuclear and membrane segmentation), and `Method of annotating images` (enum manual, semi-automated, automated) for the cell type labels PanelMaker attaches to images.

### 2.3 MITI (Minimum Information about Tissue Imaging)

Fetched: https://www.miti-consortium.org/ , https://github.com/miti-consortium/MITI , https://raw.githubusercontent.com/miti-consortium/MITI/main/README.md , and the eight YAML files under https://raw.githubusercontent.com/miti-consortium/MITI/main/yaml/ (`01-clinical.yaml`, `02-biospecimen.yaml`, `03-file.yaml`, `04-channel.yaml`, `05-ome-tiff-header.yaml`, `06-processed-data.yaml`, `07-cell.yaml`, `08-cell-state.yaml`). The paper is Schapiro et al., Nature Methods 2022, https://doi.org/10.1038/s41592-022-01415-4 (the Nature page redirected to a login gate, so the paper text itself was not fetched; the site and repo state the DOI and the arXiv preprint https://arxiv.org/abs/2108.09499).

What it is. Minimal metadata for highly multiplexed tissue images from the Human Tumor Atlas Network community. Each attribute has `description`, optional `category`, `type` (`boolean`, `integer`, `float`, `string`, `filename`, `date` ISO 8601, `doi`, `rrid`), optional `valid-values` (keyword list or min/max), and `significance` (`required` or `recommended`, sometimes conditional such as `required: SizeZ > 1`). MITI does not use ontology ids; its controlled vocabularies are keyword lists.

Levels and the fields that matter to PanelMaker:

- Clinical (`01-clinical.yaml`, cancer-registry style, 35+ attributes): `Participant ID`, `Species`, `Ethnicity`, `Gender`, `Race`, `Age at diagnosis`, `Primary diagnosis`, `Morphology`, `Site of resection or biopsy`, `Tissue or organ of origin`, `Tumor grade`, treatment fields. Mostly out of PanelMaker's scope; `Species`, `Age at diagnosis`, and `Tissue or organ of origin` overlap.
- Biospecimen (`02-biospecimen.yaml`): `Biospecimen ID`, `Parent ID`, `Adjacent Biospecimen ID`, `Biospecimen Type` (Tissue, Bone Marrow, Cell Block, Blood, Fluids), `Analyte Type`, `Protocol Link` (doi), `Timepoint Label`, `Collection Days From Index`, `Acquisition Method Type` (Autopsy, Biopsy, Fine needle aspirate, Surgical Resection, ...), `Post-mortem Interval`, `Tumor tissue type`, `Preservation method` (`Formaldehyde fixed paraffin embedded (FFPE)`, `Frozen`), `Fixative Type` (string), `Fixation Duration` (integer, minutes), `Slide Charge Type` (Uncharged, Charged, Coverslip, Coated, Not applicable), `Section Thickness Value` (float, microns), `Days to sectioning`, `Storage Method` (Ambient temperature, 4C, -20C, -80C), `Days to processing`, `Shipping Conditions`, histology assessment fields (`Histology Assessments By`, `Percent Tumor Cells`, ...), imaging prep: `Fiducial marker` (Nuclear Stain (DAPI), Fluorescent beads, Grid slides (hemocytometer), Adhesive markers), `Mounting medium` (Aqueous, Non-Aqueous, Xylene, Toluene, Antifade with DAPI, Antifade without DAPI, PBS), `Slicing method` (Vibratome, Cryosectioning, Tissue molds, Sliding microtome, Sectioning), `Control` (Cell line, tissue, mutation, matrix, metal coating, fiducials).
- Imaging assay file (`03-file.yaml`): `Data File Id`, `Filename`, `File Format` (SVS, OME-TIFF, CZI), `Channel-Level Metadata Csv Filename`, `Imaging modality` (epifluorescence, lightsheet, confocal, ion beam, laser ablation), `Assay Type` (H&E, t-CyCIF, IHC, mIHC, MxIF, SABER, IMC, CODEX, MIBI), `Protocol Id(S)` (doi), `Acquisition software`, `Image Acquisition Date`, `Microscope`, `Objective`, `Nominal Magnification` (10X, 40X), `Lens NA`, `Working Distance` and unit, `Immersion Medium` (Air, Water, Glycerin, Oil), `Frame_ Averaging`, `Fov_Number`, `Fov_Sizex`, `Fov_Sizey` (microns), `Pyramid`, `Z_Stack`, `T_Series`, `Comment`.
- Channel (`04-channel.yaml`), all required unless noted: `Channel ID`, `Channel Name` (must match OME-XML), `Cycle Number` (recommended, integer >= 1), `Sub-Cycle #` (recommended), `Target name`, `Antibody Name`, `RRID identifier` (type rrid), `Fluorophore`, `Clone`, `Lot`, `Vendor`, `Catalog #`, `Excitation wavelength`, `Emission wavelength`, `Excitation bandwidth`, `Emission bandwidth` (recommended, nm), `Metal isotope: Element`, `Metal isotope: Mass`, `Oligo barcode: upper strand`, `Oligo barcode: lower strand`, `Dilution` (recommended), `Concentration` (recommended), `Passed QC` (recommended), `QC details`, `Comment`.

What PanelMaker should adopt. The channel YAML is, field for field, the record PanelMaker already tries to capture per antibody row; adopt its names for the new channel-level fields: `Cycle Number`, `Sub-Cycle #`, `Excitation wavelength`, `Emission wavelength`, `Excitation bandwidth`, `Emission bandwidth`, `Metal isotope: Element`, `Metal isotope: Mass`, `Oligo barcode: upper strand`, `Oligo barcode: lower strand`, `Concentration`, `Lot`, `Passed QC`, `QC details`. Because MITI uses keyword lists rather than ontology ids, PanelMaker should store the MITI keyword and, where one exists, the ontology id alongside (section 3).

How PanelMaker could import OMAPs and ASCT+B.

- OMAP CSV to Panel: one OMAP becomes one `Panel` (name from the title row, `speciesId` NCBITaxon:9606, `tissueId` from `organ_uberon`, method from `method`, fixation from `tissue_preservation`, new fields `protocolDoi`, `authorOrcids`, `sourceOmapId`, `sourceVersion`, `dataDoi`). Rows group by `cycle_number` into `PanelCycle` (name `Cycle {n}`, new integer `cycleNumber`). Each row becomes a `PanelMarker`: `proteinId` from `uniprot_accession_number` (upsert Protein with `geneSymbol` = `target_symbol`, new `hgncId` = `HGNC_ID`), `antibodyId` by upserting `Antibody` on `rrid` (host via NCBITaxon lookup of `host`, `cloneId`, `clonality`, new `isotype`, new `recombinant`, `vendorName`, `catalogNumber`, `conjugate`), `fluorophoreId` by alias matching `conjugate` or `fluorescent_reporter` to the Fluorophore table (AF488 to Alexa Fluor 488 needs an alias map), new `dilutionFactor`, `concentrationValue`, `lotNumber`, `isCorePanel`, `rationale`. The concrete column mapping is in section 4.3.
- ASCT+B to cell type marker evidence: for each `cell_types[]` entry with a CL id, for each `has_characterizing_marker_set[].members` HGNC id, resolve HGNC to UniProt (UniProt id mapping or the HRA `/ensembl-lookup` plus Ensembl to UniProt cross reference) and upsert `CellTypeMarker` with `source` = `ASCT+B {organ} {version}` and `isCanonical` = true when the set carries `references`. `ccf_located_in` gives UBERON structures per cell type, which can populate a new `CellTypeTissue` link and improve the tissue-constrained cell type suggestions. Provisional `ASCTB-TEMP` cell types should be skipped or stored as free text.
- AVR JSON to validated reports: each AVR record is a HuBMAP-validated `ExperimentalReport` (antibody by `rrid`, organ by `organ_uberon_id`, method, tissue preservation, antigen retrieval text, dilution or concentration, cycle number, `recommended` maps to `recommendation`), attributable to `author_orcids` and `protocol_doi`.

## 4. Proposed export and import formats

### 4.1 SDRF-style tab-separated export for a PanelMaker experiment

Design: one row per (sample, image or ROI, channel). `source name` identifies the sample (donor plus block plus slide), `assay name` identifies the image or region of interest, and the channel columns distinguish rows that share an `assay name`, mirroring how SDRF handles multiplexed MS runs. Column names in the first group are real SDRF terms with the ontologies SDRF assigns; the columns marked (ext) are PanelMaker extensions that do not exist in the SDRF term list and would fail strict `parse_sdrf` validation until an imaging template is registered with bigbio/sdrf-templates. Values use the `NT=...;AC=...` form wherever an id exists, and the reserved words `not available` and `not applicable` otherwise.

### 4.3 OMAP CSV to Panel, PanelCycle, PanelMarker

## 6. Prioritized recommendations

Scope note (2026-09-22): PanelMaker's primary target is imaging-based, antibody-based multiplexed immunofluorescence. Everything below is ordered for that use case first. Metal-tag imaging (IMC, MIBI) and mass spectrometry are later extensions: the schema must not exclude them (keep the `detection` discriminator on imaging methods and leave metal and oligo fields nullable), but no work item should be blocked on them. Concretely: the fluorescence channel fields, FPbase spectra, the EFO fluorescence assay terms, MITI channel and antibody fields, and OMAP import come first; metal element and mass columns can land in the same migration only if they cost nothing extra; SDRF-Proteomics templates and PRIDE cross-links are deferred.

Effort: small = under a day, medium = a few days, large = a week or more including migration and UI.

1. Normalize taxon ids to `NCBITaxon:` CURIEs and switch species search to OLS4 `ncbitaxon` (small). Touch points: `src/lib/ontology.ts` (`searchSpecies`), `src/components/submit/types.ts` (`extractOrganismId` already parses the trailing digits, so it keeps working), a data migration for `Taxon.id`, `Experiment.speciesId`, `Antibody.hostTaxonId`, `Panel.speciesId`, and the seed scripts under `scripts/` and `prisma/` (`seed-demo.ts`, `reference.ts`, `data/`). Add `revalidate` to whichever species fetch remains.

2. Add term-by-id lookup, obsolete checks, and hierarchy helpers to `src/lib/ontology.ts` (small). New functions `getTerm(ontology, id)` using `/api/ontologies/{onto}/terms?obo_id=`, `getAncestors(ontology, iri)` using `hierarchicalAncestors`, and `searchWithin(ontology, q, parentIri)` using `childrenOf`. Pass `obsoletes=false` explicitly. Use them to populate `CellType.parentIds`, `Tissue.partOfIds`, `CellularComponent.partOfIds` on upsert (currently always `[]`), to re-validate stored ids nightly (the `HsapDv:0000087` case shows terms do go obsolete), and to scope cell type search to the experiment organ. Touch points: `prisma/schema.prisma`, `src/models/experimental-report/schema.ts` (`batchContextSchema`), `src/models/experiment/schema.ts`, `src/components/submit/experiment-method-section.tsx`, `src/components/submit/types.ts`, the experiment detail page.

Order of execution for the immunofluorescence-first roadmap:

1. Foundation: 1 (NCBITaxon CURIEs), 2 (OLS4 term lookup and hierarchy helpers), 3 (ImagingMethod table seeded from the EFO spatial proteomics branch, fluorescence terms first, `detection` column kept so mass-based methods slot in later).

4. Specimen and donor: 4 (preservation, fixative, antigen retrieval text, section thickness, sex, age, developmental stage, protocol DOI).

7. Image level: 14 (pixel size, channels, objective, external dataset links).
